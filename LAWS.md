# LAWS — Bush League

The constitution. These change only by explicit, recorded decision in `DECISIONS.md`. Each law carries its reason, because a law whose purpose is forgotten gets "cleaned up" by a well-meaning future pass.

> **Laws 1, 13 and 17 are SUPERSEDED — see `DECISIONS.md` D78, 2026-09-04.** The engineering substrate
> moved from a hand-composed single HTML file to React + TypeScript + Vite on a pnpm workspace, hosted
> on GitHub Pages. Left in place below, not deleted, per this project's own rule: a superseded entry is
> a record of what was decided and why, not an error to erase. Everything else in this file — the books
> law, the token law, hidden truth, phone-first, the tier discipline — is unaffected and still binds.

1. ~~**One self-contained HTML file.** No frameworks, no build step, no CDNs, no split CSS/JS.~~ *Why it existed: portability was the product — the game had to open anywhere, forever, from one file. D78 trades that for a PWA-installable hosted app instead: not the same guarantee (a device needs one first connection), but the closest available match to the same reason, chosen deliberately rather than dropped.*
2. **One state object `G`, plain JSON only.** No classes, Dates, functions, or DOM refs in state. `JSON.stringify(G)` IS the save; `freshState()` defines the entire schema with comments. *Why: anything outside `G` silently resets on reload.*
3. **Anything that compounds lives in `G`**, never in a module-level constant. *Why: the most expensive drift bug — a reload changes what next week costs.*
4. **The books law: nothing touches cash except `post()`.** Double-entry; every cash movement is a balanced journal entry; statements are pure views over the ledger; `auditBooks()` ships inside the game and must return clean. *Why: an event that doesn't post didn't happen; the books must prove themselves.*
5. **The table law: every tabular surface runs through the one shared grid engine.** Columns, saved views, filters, multi-sort, CSV export, phone list mode. No bespoke tables per tab. *Why: a fix anywhere is a fix everywhere; phone mode works everywhere.*
6. **The token law.** Every colour, size, spacing, radius, weight, and duration is a `:root` custom property defined exactly once; feature CSS uses only `var(--token)`; no selector defined twice. Tabular numerals, 1px hairlines, SVG charts. *Why: crispness is a checklist, not a vibe; one source of truth for the look.*
7. **Render is pure.** Each tab is a view function returning an HTML string; a `VIEWS` map routes; view functions never mutate `G`. After any mutation: repaint KPIs, repaint view, autosave. *Why: rendering that mutates state makes bugs unreproducible.*
8. **One event system.** Every interactive element is `data-act` dispatched through one delegated document click handler into an `ACTIONS` map, inside try/catch. Args split on `|` — never put `|` inside an arg. *Why: innerHTML re-renders must stay cheap; per-element listeners leak and die.*
9. **One clock.** `advanceDays(n)` → `tickDay()` → `settleWeek/Month/Year` fired from real calendar boundaries, guarded by an `advancing` flag. ALL simulation happens in the settle functions. Period closes run BEFORE the new period's charges post. Re-render once per batch. *Why: double-ticks and close-order bugs are the classic economy poisoners.*
10. **Hidden truth, noisy estimates.** True ratings are never displayed, anywhere. The player sees 20–80 scout grades with noise and a reliability that grows through looks and sample size. *Why: this uncertainty is the soul of the game; one leak breaks it permanently.*
11. **Saves are forever.** Every schema change backfills old saves in `migrate()`. Never tell Jordan to wipe a save. *Why: a dynasty spans decades of sim time across dozens of builds.*
12. **Every number carries a tier.** Tier 1 exact against a real document (ship-blocking if wrong) · Tier 2 within a stated tolerance of a real distribution · Tier 3 labelled estimate. Derive content from published data; **if a number isn't in `RESEARCH.md`, research it and add it with a source — never silently invent.** *Why: an invented number is indistinguishable from a sourced one six weeks later, and it propagates.*
13. ~~**The changelog.** A `BUILD` const at the top of the file gets a `Build X.Y · NAME. description…` line prepended every pass, newest first.~~ *Why it existed: the file carried its own history; the folder's changelog regenerated from it. There is no more single file to carry a `BUILD` const — `CHANGELOG.md` is now the primary record, versioned against `package.json` and git tags.*
14. **Names matter.** Generator banks with real flavor for players, coaches, rivals, events. Never `Player_1`. *Why: the living world dies the moment a name looks generated.*
15. **Phone-first.** Designed at 360px, verified at 360px, every pass. *Why: Jordan plays on an Android phone; desktop is the secondary surface.*
16. **The engine is pitch-aware under the hood from day one**, even while v1 outputs only box scores. At-bat and pitch layers are later camera zooms over the same math, not new engines. *Why: retrofitting pitch logic under seasons of accumulated stats breaks the statistical continuity of saves — and Road to the Show depends on the zoom.*
17. ~~**Deliver the complete single file every pass — never a diff, never split parts.**~~ *Why it existed: diffs desync from disk silently, and the desync is expensive. Applies now to the repository as a whole instead: every pass leaves `main` green (CI passing, deployed) rather than handing over an artifact file — the repo is always the source of truth, never a zip.*
